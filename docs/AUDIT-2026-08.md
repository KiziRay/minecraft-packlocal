## 各項細節

### #1 Origins/Apoli（路徑感知的重點）
- 掃描位置：`datapacks/`、`kubejs/data/`、實例頂層 `data/` 下，路徑經過
  `data/<ns>/{powers|origins|origin_layers}/` 的 `.json`。
- 只翻 `name`／`description`。**排除**祖先鍵為
  `condition(s)`／`action(s)`／`modifier(s)`／`predicate(s)`／`filter(s)` 或
  `*_condition`／`*_action`／`*_modifier` 的節點——那些 `name` 是識別字。
- 擷取與寫回共用 `is_excluded_key` 與同一套走訪，保證「掃到的才會被改、機制節點永不被動」。
  測試 `apply_only_touches_clean_nodes` 專門驗證：`condition.name` 與能力 `name` 同字串時，
  只有能力名被翻。
- **套用範圍**：`datapacks/`、`kubejs/` 來源的 Origins 會被「套用到遊戲」複製回去；
  少數放在實例頂層 `data/` 的，輸出在結果目錄但不自動套用（避免整個 `data/` 備份），
  覆蓋範圍說明會標示位置，可手動複製。

### #4 換行守衛（`placeholder.rs::fix_newlines`）
- 原文 0 換行、譯文多出 `\n` → 收斂單行（Origins/FancyMenu 面板本來就自動折行）。
- 原文多行、譯文行數變少 → 判為可能掉句 → 退回原文。
- 佔位符仍先過 `guard`，換行守衛不影響 `%s`／`{0}`。

### #6 隱私（資料流）
- 送 AI 的 payload 只有 `{i, t: 字串, c: 語境類別}`；`c` 是「物品名／介面文字…」這種
  通用類別，**不是** lang key，也不含檔案路徑或使用者身分。
- 使用者自備金鑰 → 直連上游、不經 Worker；沒填 → 經 Worker（金鑰在 secret，Worker 不記錄 body）。
- 本機檔：`secrets.json`（gitignore）、`glossary.json`、`tm.json`；皆不外傳。

### #8 限流緩解層次
1. 客戶端：代管模式並行降到 4（好公民），429 指數退避。
2. Worker：`DAILY_TOKEN_BUDGET`（需 KV；目前 token 無 KV 權限，改用 DeepSeek 帳號餘額為終極上限）。
3. 建議：Cloudflare 儀表板加 Rate Limiting 規則（每 IP/每分鐘）作為第三層。
